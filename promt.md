Hi Geoff, confirmed — this is an Excel presentation issue, not a database problem. Delinquent_status is stored as plain text (NVARCHAR) in the database, and the export writes the correct string "1-30" to the CSV file. The problem is that Excel automatically reinterprets text patterns like "1-30" or "30-59" as dates when it opens a .csv file — this happens regardless of how the CSV is formatted (quoting doesn't prevent it). If you open the exported file in Notepad, you'll see the correct "1-30" text. This will affect any bucket value matching that pattern across the exports, not just this one column. There's a fix available (forcing Excel to treat specific columns as text) — let me know if you'd like it applied.
